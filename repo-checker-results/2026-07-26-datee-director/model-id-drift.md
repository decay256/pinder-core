### Finding 1: Emotional director temperature has two authoritative-looking defaults
**File**: `src/Pinder.LlmAdapters/LlmPhaseTemperatures.cs:26`; `data/prompts/emotional-reactions.yaml:94`
**Issue**: The new private director prompt declares `temperature: 0.35` in `data/prompts/emotional-reactions.yaml`, while `LlmPhaseTemperatures.EmotionalDirector` also hardcodes `public const double EmotionalDirector = 0.35`. The runtime call in `src/Pinder.LlmAdapters/PinderLlmAdapter.EmotionalDirector.cs:36` reads `prompt.Temperature ?? LlmPhaseTemperatures.EmotionalDirector`, but the entry was obtained through `RequireCompleteEntry`, whose contract requires `temperature`, so the C# constant is currently a shadow default rather than the active source of truth.
**Impact**: Future tuning can update the YAML value while leaving the C# fallback stale, or a later relaxation of `RequireCompleteEntry` can quietly re-enable the old source constant. That recreates the exact prompt/config drift surface the catalog migration is meant to avoid for per-prompt sampling settings.
**Urgency**: U3 - topic default; no current runtime divergence because the YAML entry is required today, but the duplicate default is drift-prone.
**Fixer-Agent Action Plan**: Pick one owner for the director sampling defaults. Prefer making `emotional-reaction-director` fully YAML-owned by removing the `LlmPhaseTemperatures.EmotionalDirector` constant and replacing the null-coalescing fallback with the already-required `prompt.Temperature.Value` / `prompt.MaxTokens.Value`, or alternatively move the director out of per-prompt sampling and document/code it as an adapter-level phase like the other `LlmPhaseTemperatures` entries.
