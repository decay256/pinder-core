### Finding 1: Duplicate JSON fields are silently collapsed before director contract validation
**File**: `src/Pinder.LlmAdapters/EmotionalDirectorContract.cs:189`
**Issue**: The strict emotional director parser calls `JToken.Parse(json!)`, then validates the resulting `JObject` with `HasOnlyProperties` and per-field `TryGetValue`. Newtonsoft's default duplicate-property handling collapses duplicate object properties during parse/load, so an output such as two `primary_emotion` fields reaches validation as a single value instead of being rejected as an ambiguous contract violation. The #1341 rejection matrix covers missing, unexpected, blank, short, meta, mechanics, symbolic-only, and drafted-reply failures in `tests/Pinder.LlmAdapters.Tests/Issue1341_EmotionalDirectorContractTests.cs:93`, but it has no duplicate-field rejection case.
**Impact**: The director contract claims an exact seven-field private direction object, but malformed generated JSON can be accepted after one duplicate value silently wins. That makes the fail-fast boundary dependent on parser overwrite behavior rather than the explicit schema/contract, and can let contradictory or prompt-injected director instructions proceed into retry-accepted output without a contract violation diagnostic.
**Urgency**: U1 - topic default because malformed LLM contract output can be silently accepted on a production LLM path instead of failing loud and retrying.
**Fixer-Agent Action Plan**: Add a regression with duplicate required fields, preferably one invalid then one valid and one valid then one invalid. Parse with duplicate-name rejection, for example by loading through a `JsonTextReader` plus `JsonLoadSettings { DuplicatePropertyNameHandling = DuplicatePropertyNameHandling.Error }`, map the resulting `JsonException` to a stable sanitized reason such as `duplicate_field` or `malformed_json`, and verify both native structured and non-native extraction paths reject duplicates.
