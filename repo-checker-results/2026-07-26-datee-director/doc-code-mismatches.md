### Finding 1: Prompt SSOT file layout omits most current prompt YAML files
**File**: `docs/prompts.md:58`
**Issue**: The document says it is "the authoritative map of every LLM prompt template" and its "File layout (Current SSOT)" lists only `templates.yaml`, `archetypes.yaml`, `structural.yaml`, `narrative.yaml`, `overlay-model-comparison.yaml`, `emotional-reactions.yaml`, and `stake.yaml`. The actual `data/prompts/` directory also contains `backstory.yaml`, `backstory_consolidation.yaml`, `bio.yaml`, `character-generation.yaml`, `diagnosis.yaml`, `dramatic_arc.yaml`, `outfit.yaml`, `personality_consolidation.yaml`, and `sim_agent.yaml`.
**Impact**: Someone using this page as the authoritative prompt map can miss live prompt surfaces that are loaded by `PromptCatalog.LoadFromDirectory`, including `diagnosis.yaml`, which feeds the #1340/#1341 emotional-director input path through therapist diagnosis fields.
**Urgency**: U3 - topic default; this is documentation drift, not an immediate runtime behavior break.
**Fixer-Agent Action Plan**: Update the `docs/prompts.md` file layout to enumerate every current `data/prompts/*.yaml` file, or replace the hand-maintained list with a generated/checkable inventory. Keep `emotional-reactions.yaml` documented as the director-specific entry, but make the surrounding map complete.

### Finding 2: Module docs still describe PromptTemplates entries as const strings
**File**: `docs/modules/llm-adapters.md:17`
**Issue**: The key-components table describes `PromptTemplates.cs` as "Static instruction templates", and the API section labels `DialogueOptionsInstruction`, `DateeResponseInstruction`, `InterestBeatInstruction`, and the `DateeReaction*` entries as `const string`s. The actual `src/Pinder.LlmAdapters/PromptTemplates.cs:11` states that "all const-string prompt content has been deleted", and the properties now call `GetCatalogString(...)` against the YAML-backed `PromptCatalog` (for example `DialogueOptionsInstruction => GetCatalogString("dialogue-options-instruction")` at `src/Pinder.LlmAdapters/PromptTemplates.cs:71`).
**Impact**: Maintainers extending #1341-era prompt behavior can look for embedded constants or assume changing `PromptTemplates.cs` edits prompt content, when the production source of truth is now `data/prompts/*.yaml` plus runtime catalog validation.
**Urgency**: U3 - topic default; stale API docs can mislead future prompt edits, but the runtime code currently fails fast through the catalog.
**Fixer-Agent Action Plan**: Rewrite the `PromptTemplates` section to describe it as a YAML-backed compatibility facade, remove `const string` labels for catalog-backed properties, and point content edits to the relevant YAML files.

### Finding 3: Emotional-director fallback docs omit structured non-native JSON extraction
**File**: `docs/modules/llm-adapters.md:76`
**Issue**: The #1341 section says `GenerateEmotionalDirectionAsync` prefers `IStructuredLlmTransport` and "falls back to local JSON extraction for plain text transports." The implementation also uses local JSON extraction for structured transports when the response is not native structured output: `ParseEmotionalDirectorOrThrow(... requireCompleteJsonObject: structuredResponse.UsedNativeStructuredOutput, ...)` passes `false` when `UsedNativeStructuredOutput` is false, and `EmotionalDirectorContract.TryParse` then calls `GeneratedJsonObjectExtractor.TryExtractFirstValidObject` at `src/Pinder.LlmAdapters/EmotionalDirectorContract.cs:171`. The scoped regression `StructuredTransport_NonNativeResponseUsesLocalJsonExtraction` in `tests/Pinder.LlmAdapters.Tests/Issue1341_EmotionalDirectorContractTests.cs:57` confirms that Markdown/prose-wrapped JSON from a structured transport is accepted.
**Impact**: Provider/transport maintainers can incorrectly assume non-native structured responses must already be complete JSON, or that local extraction is only available on plain transports, which makes the documented contract narrower than the adapter actually supports.
**Urgency**: U3 - topic default; this is a docs precision issue around fallback semantics, with tests preserving the runtime behavior.
**Fixer-Agent Action Plan**: Change the #1341 docs to say local JSON extraction is used for plain transports and for structured responses whose `UsedNativeStructuredOutput` flag is false; reserve complete-object parsing for native structured output.
